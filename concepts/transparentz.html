Your redundancy question, answered

When is a 2nd (or 3rd) backup worth it?

Rule of thumb: add a backup only where a single point of failure breaks a promise. TransparentZ makes 3 promises — points are real, the app keeps working, privacy is honored — so those get redundancy. Everything else can fail loudly and that's fine.

1 method

Convenience features (cosmetics, fancy charts). If it's down, shrug. No backup. Don't gold-plate.

2 methods

Anything a user paid for or that holds their data (saves, points, builds). Primary + one fallback. The sweet spot for almost everything.

3 methods

Only the trust core: verification + the points ledger. Cheating-proof & outage-proof & privacy-proof needs primary + cloud + local-offline.

The trick: design so the local-offline path is always a complete product on its own (this matches Aether's “local-first” pattern from Jarvis). Then cloud is pure upside, “downed service” is a slowdown not an outage, and “ultimate privacy” is just turning the cloud off — not a separate codebase.

My recommendation

Combine

Don't build a second tier system or a second honesty engine. Reuse Aether's tiers.ts palette and zScore/confidenceFromZ as a tiny shared package. One source of truth, two apps.

Trim

For v1, ship only: the 4 completion tiers, the Points Forge, local verification, and the free build-it-yourself lesson. Cloud sync, subscriptions, leaderboards, and Backup-2/3 come after the core feels good.

One main goal, said plainly: “Finish games honestly, earn points you can prove, and learn the toolchain doing it.” Everything else is a dial you turn up later.
