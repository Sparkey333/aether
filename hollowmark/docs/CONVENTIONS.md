# HOLLOWMARK — Code Conventions & Shared Contracts

These rules keep six independently-authored systems compiling and cooperating
in one Unity project. **Read this before writing any code.**

## Project facts

- **Unity 6** (`6000.0.x`), **URP 17**, **Input System 1.11** (code-defined
  actions — see `InputReader`), single default assembly (no asmdefs).
- Editor-only code lives ONLY under `Assets/_Project/Code/Editor/`
  (Unity's special-folder rule makes it editor-only).
- Scenes, materials, and assets are **generated by the editor bootstrap** —
  runtime code must never assume a hand-authored scene exists.

## Namespaces & folder ownership

| Folder (`Assets/_Project/Code/…`) | Namespace | Owns |
|---|---|---|
| `Core/` | `Hollowmark.Core` | shared contracts (DO NOT MODIFY) |
| `Player/` | `Hollowmark.Player` | motor, controller, orbit camera |
| `Combat/` | `Hollowmark.Combat` | Splitfang, gun cores, projectiles, melee |
| `Hollow/` | `Hollowmark.Hollow` | Hollow form, meters, lash |
| `Enemies/` | `Hollowmark.Enemies` | Rend AI, spawner, boss |
| `Skiff/` | `Hollowmark.Skiff` | hoverboard, mounting |
| `Systems/` | `Hollowmark.Systems` | game manager, checkpoints, sparks, save, missions |
| `UI/` | `Hollowmark.UI` | runtime-built HUD |
| `Editor/` | `Hollowmark.EditorTools` | bootstrap menu |

Write only inside your assigned folder. Reference other systems through the
`Core` contracts and `GameEvents` where possible.

## Hard API rules (Unity 6 correctness)

- `Object.FindFirstObjectByType<T>()` / `FindObjectsByType<T>(FindObjectsSortMode.None)`
  — **never** the removed/deprecated `FindObjectOfType`.
- Input **only** via `Hollowmark.Core.InputReader` — never `UnityEngine.Input`
  (the old Input Manager is disabled when the Input System package is active).
- **No `UnityEditor` usage in runtime folders.** No `OnGUI`/`GUILayout`.
- UI is UGUI. Text uses **legacy `UnityEngine.UI.Text`** with
  `Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")` — **no TextMeshPro**
  (TMP needs its Essentials import; we want zero-setup).
- Camera is the hand-rolled `OrbitCamera` — do not reference Cinemachine yet.
- **Tags:** only built-ins. The player root is tagged `"Player"` (built-in tag,
  set by the bootstrap). Prefer component lookups
  (`GetComponentInParent<...>()`) over tags where practical.
- **Layers:** built-ins only (`Default`, `Ignore Raycast`, `Water`, `UI`).
  No `LayerMask.GetMask` with custom names. Exclude self-hits by checking the
  hit collider's root, not by layer.
- Materials created at runtime use `Shader.Find("Universal Render Pipeline/Lit")`
  (null-check the result) or tint via `MaterialPropertyBlock` with the
  `_BaseColor` property.
- Coroutines are fine; no `async/await`, no per-frame LINQ.

## Defensive-coding rules (nobody here can compile)

- Every `[SerializeField]` reference must be null-guarded with a
  `Debug.LogWarning` naming the missing piece — a half-wired scene must never
  NullReference-spam.
- Components that need scene-singletons call their `EnsureExists()` /
  static-instance patterns rather than assuming setup order.
- Anything subscribing to **static** `GameEvents` or another object's C# event
  MUST unsubscribe in `OnDestroy`/`OnDisable`.
- Prefer boring, long-stable Unity APIs over clever ones.
- Keep each file under ~350 lines. `[Header]`, `[Tooltip]`, `[Range]` on
  tunables. Comments only where behavior is non-obvious.

## Shared contracts (already written — build against these exactly)

`Hollowmark.Core` provides:

- **`Faction`** — `Player, Ironwatch, Rend, Neutral`.
- **`DamageInfo`** — struct: `Amount, Source (GameObject), Point, Normal,
  Knockback (Vector3), SourceFaction, FromHollow`.
- **`IDamageable`** — `void TakeDamage(in DamageInfo info); Faction Faction { get; }; bool IsDead { get; }`.
- **`Health : MonoBehaviour, IDamageable`** — `Max`, `Current`, `Normalized`,
  `IsDead`, events `Changed(current,max)`, `Damaged(DamageInfo)`,
  `Healed(float)`, `Died`; methods `Heal`, `SetMax`, `ReviveFull`.
  Applies `PlayerBuffs.DamageTaken` when its faction is `Player`.
- **`PlayerBuffs`** — static multipliers `MoveSpeed`, `MeleeDamage`,
  `GunDamage`, `DamageTaken` (+ `ResetAll`). Hollow form writes these;
  motor/melee/gun read them every use.
- **`InputReader : MonoBehaviour`** — singleton (`Instance`,
  `EnsureExists()`). Polled state: `Move` (Vector2), `Look` (pointer delta,
  px/frame), `LookStick` (gamepad -1..1, scale by deg/sec * dt), `JumpHeld`,
  `FireHeld`. Events: `JumpPressed/Released`, `DashPressed`, `MeleePressed`,
  `FirePressed/Released`, `SwapCore(int direction)`, `TransformPressed`,
  `InteractPressed`, `MountPressed`.
- **`GameEvents`** — static events + `Raise*` methods:
  `PlayerSpawned(GameObject)`, `PlayerDied()`,
  `EnemyKilled(GameObject, DamageInfo)`, `SparksChanged(int delta, int total)`,
  `CheckpointActivated(Vector3 respawnPoint)`,
  `BossHealthChanged(string name, float normalized)`,
  `Announce(string message)`.

## Cross-system flow (who talks to whom)

- `PlayerController` raises `PlayerSpawned` in `Start` and after respawn;
  HUD/enemies/camera acquire the player from that event (with
  `FindFirstObjectByType` fallback).
- Enemies raise `EnemyKilled` on death → Hollow meter fills, missions count.
- Hollow form writes `PlayerBuffs`; motor/melee/gun read them.
- `Checkpoint` raises `CheckpointActivated` → `GameManager` stores respawn.
- Boss raises `BossHealthChanged` → HUD bar. Anything can `Announce("WAVE 2")`.
- Placeholder visuals only: primitives, `LineRenderer`, color tints. No file
  assets, no asset store.
