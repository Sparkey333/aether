# Output Style

> How I like the *output*: code, prose, commits. Train this from what I keep
> accepting and what I keep changing.

## Code
- Match the surrounding file's conventions before importing my own.
- Clarity over cleverness; small functions; names that say what they do.
- Comment the *why*, not the *what*. Match the file's existing comment density.
- No dead code, no speculative abstraction for a future that isn't here yet.

## Prose / docs
- Plain, direct, a little warmth. Short sentences. Active voice.
- Lead with the conclusion. Use tables when comparing, lists when sequencing.

## Commits
- Imperative subject, ≤ ~70 chars: "Add X", "Fix Y", not "Added/Fixes".
- Body explains *why* when it isn't obvious from the diff.
- One logical change per commit where practical.
